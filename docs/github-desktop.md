# Working with GitHub Desktop

The repository is already set up for GitHub Desktop. `origin` points at
`https://github.com/NathanielJames97/gennytracks.git` and `master` tracks it.

## First-time setup

1. Open GitHub Desktop and choose **File → Add existing repository**.
2. Select `D:\LeccyTrack\gennytracks` — point it at the folder containing
   `.git`, not at `D:\LeccyTrack`.
3. GitHub Desktop will find the `origin` remote already configured and show
   **7 commits ahead**. Nothing needs re-cloning.

## The normal loop

```bash
# before you start
git pull

# after you finish
npm run build:data   # if data/ changed
npm run build        # confirm it compiles
npm test
```

Then press **Commit to master** in GitHub Desktop (give the changes a summary)
and **Push origin**.

Keep `npm run build:data` and `npm test` in the terminal rather than in GitHub
Desktop. GitHub Desktop does not run npm scripts, and the data build takes about
40 seconds and needs `--max-old-space-size=6144`, so it belongs in a shell.

## What is and is not committed

| Path | Committed | Why |
| --- | --- | --- |
| `src/`, `scripts/`, `public/index.html` etc. | yes | the application |
| `data/source/hoc/*.csv` | yes | official HoC results, 773 KB |
| `data/source/constituency.geojson` | yes | 64 MB, a real input to `build:data` |
| `data/List of MPs … Wikipedia.html` + `_files/` | yes | 2.1 MB of source for the parser |
| `data/reference/` | **no** | 65 MB of reference SVGs no code reads; ignored, kept on disk |
| `public/data/`, `public/photos/` | **no** | generated by `build:data` |
| `build/`, `node_modules/` | **no** | generated or reinstallable |

After cloning on another machine, run `npm install && npm run build:data`
before `npm start`, otherwise the app shows "Data unavailable".

## Why `.gitattributes` is set up this way

GitHub Desktop bundles its own git and reads `.gitattributes` rather than the
machine's `core.autocrlf`, so line endings are pinned per file type instead of
depending on a global setting. Without this, a file committed from one machine
can appear as a whole-file diff on another.

The 64 MB `constituency.geojson` is marked `binary`. It is text, but nobody
diffs 64 MB of coordinates, and a line-ending normalisation would rewrite the
entire file.

## About the large files

The first push carries about 135 MB, dominated by two blobs:

- `constituency.geojson` — 64 MB, committed on purpose
- the old `2024_United_Kingdom_general_election.svg` — 65 MB, added in a local
  commit and removed again in a later one

GitHub's hard limit is 100 MB per file, so the push will succeed. The second
blob is dead weight: it is in history but no longer in the working tree. If you
want a leaner repository later, that history can be rewritten to drop it. That
rewrites commit hashes, so do it before anyone else clones — ask me and I will
do it.

Going further, `constituency.geojson` could move to Git LFS or be fetched by
`scripts/build-data.mjs` on demand. That would cut the clone to a few MB. It is
a bigger change and needs a decision about how the data is distributed, so it
is not done.

## Branch protection

GitHub Desktop will not let you force-push a protected branch. If `master`
becomes protected on GitHub, work on a branch instead:

```bash
git switch -c feature/my-change
# ... work ...
git add -A && git commit -m "Summary"
# then use "Create branch" / "Publish branch" / "Create pull request" in Desktop
```

## If something goes wrong

- **"Push rejected: fetch first"** — someone pushed. `git pull --rebase`, then push.
- **Changes show as modified after switching branches** — line-ending or filter
  interference. Run `git add --renormalize .` and commit; the `.gitattributes`
  above should prevent it recurring.
- **Large file error on push** — a file over 100 MB got committed. Find it with
  `git rev-list --objects --all | sort -k3 -n -r | head`, then add it to
  `.gitignore` and `git rm --cached`.
